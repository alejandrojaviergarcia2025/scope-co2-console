First, what is QDOAS?

QDOAS is the DOAS field's reference software — maintained by BIRA-IASB (the Royal Belgian Institute for Space Aeronomy). Feed it a measured spectrum and a reference spectrum, and it fits known gas cross-sections to whatever structure is left over between the two, using a Marquardt-Levenberg non-linear least-squares fit. It's BSD-3-Clause licensed, so nothing stops this project from adapting it directly instead of starting from zero.

QDOAS was built for atmospheric remote sensing — ground-based and satellite instruments staring through open sky — so it carries features this lab setup doesn't need: an air-mass-factor correction for slant viewing angles through the atmosphere, and an undersampling correction for scanning spectrometers. Neither applies to a sealed lab transmission cell, which actually simplifies what this project needs to configure. It ships both a desktop GUI and a command-line tool, doas_cl, driven by an XML config file — the CLI is what a Python pipeline would call.

# illustrative only — this project's own config file doesn't exist yet
$ doas_cl -c roscope_co2.xml \
          -f data/raw/2026-09-21_sample.RAW8 \
          -o results/2026-09-21_fit.nc

# roscope_co2.xml would define:
#   - the reference / dark spectra to fit against
#   - which cross-sections to include (NO2, SO2, H2O...)
#   - the fitting wavelength window

BSD-3-Clause — one of the most permissive open-source licenses that exists, the opposite of a copyleft license like GPL. Confirmed by reading the actual LICENSE file in QDOAS's repository, not assumed from the word "open source."

In practice, for this project: using QDOAS's code, porting its algorithm into Python, or calling doas_cl directly are all legally fine — for an academic ARPA-E project or otherwise. It does not force roscope_co2 to be open-sourced in return. The only real obligations: keep the copyright notice and disclaimer if redistributing its source or binary, and never use BIRA-IASB's name to promote a derived product without written permission. Then: build on QDOAS, or write our own?

QDOAS is the field's reference DOAS software — BSD-3 licensed, free to adapt. The open question is how directly to depend on it. None of these four is chosen yet.

A1

Call doas_cl directly

What it means
Generate config from Python, run QDOAS's CLI tool as a subprocess, parse its output.
Advantage
Reuses a mature, validated fitting engine.
Cost
External C++/Qt dependency to keep working.
A2

Reuse QDOAS's conventions

What it means
Adopt its reference file formats without depending on the binary.
Advantage
Reuses cross-section datasets curated by the DOAS community.
Cost
Doesn't solve the fitting engine on its own.
A3

Port QDOAS's method

What it means
Translate QDOAS's exact math into Python, without touching its code.
Advantage
Faithful to the method ARPA-E reviewers pointed us to.
Cost
Same writing effort as building our own.
B

Reimplement in Python

What it means
Write the DOAS fit directly with scipy, informed by QDOAS and the literature.
Advantage
100% in the team's own language; satellite-only features can be skipped.
Cost
More upfront work to write and validate a correct fit.

Libraries and SDKs, specifically

What's actually involved on each side, and which option is the one to evaluate first.

Core

This is the toolbox everything else is built with. Python is the language the whole project is written in; numpy and scipy do the actual math; matplotlib draws the plots.

Python 3.10+
Base language — matches Avantes' own Python-wrapped interface packages and what ARPA-E reviewers expect from a QDOAS-style adaptation.
numpy / scipy
scipy.optimize.least_squares / curve_fit are the natural tools for the DOAS non-linear fit if Option B is chosen.
matplotlib
Spectrum and calibration-curve plotting during development.

Spectrometer side (AvaSpec / AvaSoft) only if live control is ever needed

These only matter if the software should ever reach out and pull a live reading straight from the instrument. Right now, the actual need is simpler than that — just reading files AvaSoft already saved.

msl-equipment
Best-maintained, best-documented Python wrapper around the Avantes DLL — first to evaluate. From the Measurement Standards Laboratory of New Zealand.
pyava
Smaller, more focused wrapper — fallback if msl-equipment falls short somewhere.
Avantes' own samples
The AvaSpec-DLL package ships official example code in Python 3.9 with PyQt5 — a third option alongside the two wrappers above.

Reading already-exported files the actual current need

This is the piece that actually matters today — turning a file AvaSoft already saved to disk into numbers Python can work with. Nothing here talks to the instrument itself.

avaread
Most promising candidate — specifically supports the AvaSoft-8.x formats (.raw8 / .rir8 / .str8) this project's lab software produces.
pyAvantes
Apache-2.0 alternative, RAW8-specific.
lightr (R)
Not Python, but the most complete reference for the binary schema if a parser has to be written from scratch.

DAQ side (Analog Discovery 3 / Thorlabs PDA10CS-EC)

The equivalent toolbox, but for the other sensor — the one reading IR/humidity instead of UV-Vis light. Different vendor, different SDK, same basic job: turn a raw signal into numbers.

pydwf
pip-installable Python wrapper around Digilent's official WaveForms SDK. Fully independent acquisition channel from the spectrometer side.

If the QDOAS path is chosen (Option A1)

Only needed if the project ends up calling QDOAS directly. Its preferred output format needs its own reader to open reliably in Python.

netCDF4 / xarray
For reading doas_cl's NetCDF output reliably — preferable to its ASCII output, which appends instead of overwriting.
